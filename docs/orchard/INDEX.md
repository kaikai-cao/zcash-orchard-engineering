## 阶段主线（Stage A–F）

- **Stage A**：PostNu6_2 单 Action 基线（P-core 绑定，1.93 s）。
- **Stage E1**：PostNu6_3 双 Action 可重复基线（1P 3.37 s / 8P 0.93 s，3.62×）。
- **Stage E2**：源码级分阶段计时（文档 09）——定位到 quotient 55% / opening 14%，synthesis 仅 4.6%。
- **Stage E3**：CPU 采样剖析（文档 10）——quotient 内是域乘 55% + 表达式求值 30%，**FFT 子树仅 3.0%**；
  全程序 `Fp::mul` 33%、常量时间屏障 `subtle::black_box` 15%。
- **Stage F0**（文档 11）：冻结 E3 证据，统一扰动口径，登记假设 H1–H6。
- **Stage F1**（文档 12）：`Fp::mul` 微基准与汇编审计——`+bmi2,+adx` 无效（H1 否决）；
  上游手写汇编只换来 2.6% 内联吞吐；prover 里 `Fp::mul` 90%+ 未内联。
- **Stage F2**（文档 13）：把表达式树数清楚——quotient 的 1.79 s 里 **1.59 s 是求值器（89.1%）**，
  一次求值 **6570 次整块乘 × 16384 元素 = 1.076 亿次域乘**；归因**门约束 94.0%**（lookup 仅 3.9%）；
  最大单项是 **`Negated` 被实现成 `Scale(−1)`，占 38.4%**（上限 12.6%）；顺带把 H1c 从 10.6% 修正到 ≈1.8%。
- **H1c**（文档 14）：把 F1 剩下的那条假设也验掉——`lto="fat"` 不改变内联决定
  （`recurse` 体内对 `Fp::mul` 的调用点 9→9、采样叶子帧 36.67%→36.49%），端到端 **+0.00%**
  [−1.57, +1.14]，**10.6% 在 95% 置信下被排除**；`Fp::mul` 这条线关档。
- **Stage F3**（文档 15/16）：落地 **H6**——给 `Ast` 加 `Neg` 节点。
  **2638/6570 = 40.2% 的整块乘法消失**（F2 数的 38.4% 少算了 `Sub` 贡献的 112 个），
  求值器 **−31.5%**、quotient 阶段 **−28.0%**、端到端 **−14.57%**（1P，95% CI
  [−15.07, −13.91]）；其它阶段无实质变化（合计 +0.32%）。**H6 已冻结，作为 F3 的参考版本。**
- **Stage F3 · LC**（文档 17/18）：先把"叶子缓存省 0.12 s"重新核算，结论是**关档**。
  探针（零计算路径改动，proof 逐位相同）数出融合树 4632 次叶子访问只涉及 **145 个互异叶子
  （复用 31.9×）**，但 **85.5% 落在累加器位置**——那里物化的是"可写缓冲区"，不是重复读。
  可省的只有 0.311 GB / 14.4 ms / **1P 证明的 0.52%**，换 72.5 MiB 常驻。
  真正的余量在"消掉中转缓冲区"（H7，上界 4.05%），不是"缓存它"。

## 核心研究问题与四阶段答案

**问题**：「电路中占用最多行的部分，是否也是实际证明过程中最耗时的部分？」

- **E2（阶段级）**：**否。** 行数最多的 Merkle/NoteCommit 所在的 witness 执行阶段（synthesis）仅占 4.6%；
  耗时主导是 quotient（54.9%）+ opening（14.4%）= 69.3%，对全部约束一视同仁。
- **E3（函数级）**：**连"耗时主导 = FFT"也不成立。** quotient 的 1.9 s 里 85% 是域乘与表达式求值，
  FFT 子树全程序只覆盖 3.0%；另有 14.6% 是 `subtle::black_box` 常量时间屏障。
  opening 才真正是 MSM（`Buckets::sum` 覆盖 28.7%）。
- **F1（原语级）**：**"最热的函数"也不等于"最该改的函数"。** `Fp::mul` 的算术吞吐已接近该实现的
  可用水平（24 次乘法给出量级，非端口饱和证明），而它在 prover 中 90%+ 以**未内联调用**形态出现。
- **F2（结构级）**：**"最热的原语"也不等于"最该改的原语"。** 那 1.076 亿次乘法里，**38.4% 是把整块
  乘以 −1**——成本来自求值器的表达式表示，而不是 Montgomery 归约的效率。**问题从"算术快不快"
  变成"这棵树长什么样、每个节点值多少钱"。**
- **F3（语义级）**：**"最高效的优化"也不等于"最底层的优化"。** 给取负一个节点，不改一行密码学代码、
  不动 Montgomery 归约、不动 FFT，就把 40.2% 的整块乘法（2638 次 × 16384 元素）换成 4 条 `sbb`：
  quotient 快 28.0%，整个证明快 14.57%，且**求值器的收益有 92% 走到了端到端**。
  **问题从"这棵树值多少钱"变成"这棵树的语义有没有被多余地翻译成算术"。**
- **F3 · LC（结构级第二问）**：**"重复"也不等于"冗余"。** 同一个叶子被求值 31.9 次，
  直觉上该缓存；但 85.5% 的次数里，物化的产物是**要被就地修改的缓冲区**，
  换缓存只是把"旋转拷贝"换成"线性拷贝"。可省的只有 12.8% 的叶子字节、0.52% 的证明。
  **问题从"有没有重复"变成"这份重复里，有多少是产出、有多少是浪费"。**

## E1→F2 的方法链条

| 层 | 手段 | 产出 | 可信度锚点 |
|---|---|---|---|
| E1 | 墙钟计时（Keygen/Prove 分离，5 次重复） | 3.37 s / 0.93 s，3.62× | 掩码绑核，避免 E-core 污染 |
| E2 | vendor + patch，create_proof 内 9 段互不重叠计时 | 阶段占比表 | 阶段求和 vs 外层差 2.7 ms |
| E3 | 进程内统计采样（挂起线程 + DbgHelp 走栈） | 阶段×函数×行×调用者 | 逐阶段 CPU 秒 ≈ E2 墙钟秒（偏差 ≤11%） |
| F1 | 独立微基准 + 链接后二进制反汇编 + Python 大整数向量 | 4 种形态的 ns、指令构成 | 5 轮 CV < 2%；592 + 12 000 项正确性全过 |
| F2 | 结构计数（表达式/Ast 遍历）+ 隔离计时 + 逐项归因 | 节点/深度/重复/1.076 亿次域乘 | 三段归因与表达式层**逐位相符**；1.076 亿 × 10.70 ns = E3 的 33.1%（采样 vs 计数独立吻合） |
| F3 | 单因子 A/B（ABBA 交错 + 配对 bootstrap）+ 三套数据分离 | 计数、求值器、阶段、端到端四层 | 计数不变量逐位闭合；求值器 −31.5% × 份额 90.4% × 54.0% = −15.4% vs 实测 −14.6%（差 0.8 pp） |
| F3 · LC | 零改动探针（AST 位置普查 + replication bench）+ 同二进制探针开/关对照 | 叶子访问/互异/位置三分、ns/元素、可避免字节 | proof FNV 在探针开/关下**逐位相同**；`visits = ast.poly = 4632` 两条独立遍历互证；3 次计数 md5 一致 |

## 跨阶段的方法论教训

这五条不是从书上看来的，每一条都由本系列里一次具体的预测失败换来；写在这里是为了让
下一次实验开始前先对照一遍。

| 教训 | 出处 | 一句话 |
|---|---|---|
| 热点 ≠ 该改的地方 | E2 / E3 | 行数与采样占比回答"谁在花时间"，不回答"改哪里能省时间" |
| 微基准吞吐 ≠ 真实边际成本 | F1 → H6 · P2 | 孤立测一个域乘的 ns 只能给出上界；prover 里乘法在依赖链上，移除它的收益可以超过它的吞吐占比（预测 8–20%，实测 31.5%，超出自己写的 26% 上界） |
| 可测的量 ≠ 该测的量 | H6 · P2、F3 · LC | 两次栽在同一处：先用吞吐估上界，后用"全部拷贝字节"估"可避免字节"。后者数值准（0.12 s vs 实测 0.1124 s），但可避免比例只有 12.8% |
| 重复 ≠ 冗余 | F3 · LC | 同一个叶子被求值 31.9 次；其中 85.5% 是"造一块要被就地修改的缓冲区"，不是"重读没变的值" |
| 探针的惰性要用字节证明 | F3 · LC | 同一二进制、同一 seed、探针开/关下 proof 逐位相同，强于"证明能通过"（后者对某些 bug 也会通过） |
