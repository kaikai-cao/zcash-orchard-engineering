# 14 · Stage H1c 预注册：只改 LTO，到底能拿回多少

> **本文件在任何测量之前写定。** 下面第 4 节的门槛、第 5 节的预测、第 6 节的判据，
> 都在看到 LTO 构建的任何数字之前固定。如果结果落在预测之外，结论要在第 7 节
> 如实记录为"预测失败"，而不是回头改门槛。

## 1. 要检验的假设

**H1c（F1 提出，F2 降级）**：prover 里 `Fp::mul` 的调用开销可以靠**编译配置**（跨 crate 内联）拿回来。

| 版本 | 收益估计 | 依据 |
|---|---:|---|
| F1 原始 | **10.6%** | 未内联延迟 21.73 ns × 假设每次乘法都付延迟 |
| F2 修正 | **≈1.8%** | 1.076 亿次 × (10.70 − 10.14) ns ≈ 0.06 s |

两者差 6 倍。F2 的修正建立在一个**可证伪的中间量**上：prover 中 `Fp::mul` 的真实均价
是 10.70 ns（由 1.076 亿次计数与 E3 的 1.155 s 相乘反推），只比全内联吞吐 10.14 ns
高 5.5%。如果这个中间量错了，H1c 的原始估计就重新成立。

所以本实验的真正目的**不是"看 LTO 能不能提速"**，而是**给 H1c 判死刑或复活**：

- 若实测收益 ≈ 1.8% ⇒ F2 的修正成立，H1c 关档；
- 若实测收益接近 10% ⇒ F2 的 10.70 ns 反推有问题，需要回头查计数口径；
- 若实测收益 ≈ 0 且**内联确实发生了** ⇒ 调用开销本来就几乎为零，H1c 彻底关档，
  且证明"未内联"这个观察与"有成本"这个推论之间没有因果。

第三种结果是**最有信息量的**，也是最可能的。

## 2. 单因子设计

只改一个设置：`lto`。其余全部从 `release` 继承，不改一行 Rust 源码。

```toml
[profile.release]          # 冻结基线（comparison 的 A 侧）
debug = false              # opt-level 3 / codegen-units 16 / panic unwind / 无 target-cpu

[profile.lto]              # 处置组（B 侧）
inherits = "release"
lto = "fat"                # ← 唯一变量
```

**明确不动的项**（用户要求，也写在 `harness/Cargo.toml` 注释里）：

| 项 | 值 | 为什么不动 |
|---|---|---|
| `codegen-units` | 16（默认继承） | 若同时降到 1，`lto` 与 CGU 的影响混在一起，单因子失效 |
| `target-cpu` | generic（不设 `RUSTFLAGS`） | F1 已证明 `+bmi2,+adx` 无收益，不应再引入第二个变量 |
| `opt-level` | 3 | — |
| `panic` | unwind | 改 abort 会改变代码布局 |
| `debug` | false（计时）/ true（采样，见 §3.3） | 采样必须两边都带 PDB 才能对等比较 |

**为什么用 `fat` 而不是 `thin`**：`fat` 是"跨 crate 内联"这个机制的上界，与 §1
"给假设判死刑或复活"的目的相匹配。若 `fat` 都拿不到收益，`thin` 不会更好，
不必再花一个构建。若 `fat` 拿到了收益但用户不愿承担构建时间，再单独测 `thin`。

**为什么需要重新构建 A 侧**：不是要换基线，而是为了

1. 拿到 `/MAP` 符号表（冻结的 `target/release/orchard-e2e.exe` 没有符号，
   MSVC 把符号放在外部 PDB 里，而本机没有 `llvm-pdbutil`/`dumpbin`），
2. 验证 `/MAP` 是**代码生成中性**的：A 侧重建后 `.text` 的 sha256 必须与冻结二进制一致。
   若不一致，说明加了链接参数后代码变了，B 侧的对比就不干净，实验作废（见 §6 判据 P0）。

## 3. 测量协议

### 3.1 交错 A/B，而不是先跑完 A 再跑 B

跨批次绝对值漂移在 F2 里已经实测到 **6.5%**（1559 vs 1681 ms），比 H1c 的全部预期
收益（1.8%）大 3.6 倍。若 A 全跑完再跑 B，测到的是机器热状态，不是 LTO。

因此：**同一会话内交替执行**，顺序固定为 `A B A B A B A B A B`（各 5 轮），
每轮内部 `--reps 5`，取每轮的 5 个 `prove_s` 样本，合计 **25 个样本/侧**。

| 参数 | 值 |
|---|---|
| 命令 | `--mode v3 --version v3 --spends 1 --outputs 2 --reps 5 --seed 7` |
| 主指标 | `orchard_prove_s`（2 个 action = 1 spend + 1 output，与 E1 基线同一口径） |
| 1P | `RAYON_NUM_THREADS=1`，`--mask 0x1` |
| 8P | `RAYON_NUM_THREADS=8`，`--mask 0xFF` |
| A 侧二进制 | `target/h1c-baseline/release/orchard-e2e.exe`（= 冻结二进制 + `/MAP`） |
| B 侧二进制 | `target/h1c-lto/release/orchard-e2e.exe` |
| 电源计划 / 提权 | 同 F0：balanced / 非管理员（与基线冻结时一致） |

### 3.2 统计口径

- 每侧 25 个 `prove_s`：报 **中位数**、均值、CV、与 A 侧中位数之比的差值；
- 差值的不确定性用**配对 bootstrap**（按"轮"重采样，5 对，10 000 次）给出 95% 区间，
  而不是假设正态；
- **不以单次跑赢 1% 作为结论**。1P 的 CV 是 1.86%，单轮差值落在噪声里就照实说。

### 3.3 内联验证（这是 H1c 的**机制**证据，缺了它整个实验只是"改了个开关"）

| 检查 | 做法 | 期望 |
|---|---|---|
| C1 | A/B 两侧都用 `-C link-arg=/MAP:<file>` 链接，从 map 中取 `evaluate::recurse` 的 RVA 与长度 | 符号存在且可定位 |
| C2 | `objdump -d` 反汇编 A/B 二进制，切出 `recurse` 函数体，数其中 `call` 指令的条数与目标 | A：`recurse` 体内有 `call` 指向 `Fp` 乘法符号；B：同位置**不再有**该调用 |
| C3 | 全二进制统计"调用 `Fp` 乘法的 `call` 条数" | B 显著少于 A（不一定为 0：其他调用者仍可能存在） |
| C4 | E3 采样（`--mode profile --e3-out ... --e3-interval-ms 4`，`target/sampling` vs `target/lto-sampling`） | `Fp::mul` 作为**叶子帧**出现的样本数大幅下降，`evaluate::recurse` 的 self 份额相应上升（时间不会消失，只是换了归属） |

C4 的预期是本文件最容易被打脸的一条：如果 B 侧 `Fp::mul` 的 self 占比**没变**，
说明 LTO 根本没内联它，那么无论 §3.1 测出什么，H1c 的机制都不成立。

## 4. 决策门槛（先定，后测）

以 1P 的配对差值 `Δ = (median_B − median_A) / median_A` 为准（负值 = 变快）。
8P 只作旁证：8P 的 CV 更小（1.05%）但核间干扰更大，不单独作为判据。

| 门 | 条件 | 结论 | 后续动作 |
|---|---|---|---|
| **G-A** | `Δ ≤ −5%` | F2 修正被推翻，H1c 复活 | 回头查 10.70 ns 反推（计数口径/采样分母），并把 LTO 列入发布配置 |
| **G-B** | `−5% < Δ ≤ −1%` 且 95% 区间不跨 0 | 收益真实，与 F2 的量级相容 | 记录数值，作为"可选发布配置"，不进 F3 主线 |
| **G-C** | `\|Δ\| < 1%` 或区间跨 0 | **无可测收益** | H1c 关档（结论：调用开销已被 ILP 掩盖，inline 与否不影响吞吐），F2 的 1.8% 上限未被违反 |
| **G-D** | `Δ ≥ +1%` | LTO 有害（代码膨胀 / I-cache） | 记录并关档 |

**无论哪个门命中，都要报一件事**：Δ 的 95% 区间上界是多少。若上界 < 10.6%，
F1 的 10.6% 在统计上被证伪——这是本实验**必定**能交付的结论，比"省了几个百分点"更重要。

## 5. 事前预测（可打脸）

| 项 | 预测 | 若不符 |
|---|---|---|
| 1P `Δ` | **−0.5% ~ −2.5%**，中位约 **−1.5%** | 见 §4 |
| 8P `Δ` | 与 1P 同向、同量级（LTO 不改变并行结构） | 说明 8P 的行为另有原因，需查 |
| C2：`recurse` 体内对 `Fp` 乘法的 `call` | A ≥ 1 条，**B = 0 条** | B 仍 > 0 ⇒ LTO 未内联该函数 ⇒ H1c 机制不成立 |
| C4：`Fp::mul` 叶子帧样本 | B 比 A 少 **≥ 80%** | 少 < 50% ⇒ 内联只发生了一部分，与 C2 交叉核对 |
| 二进制体积 | B 比 A **小**（消除重复单态化） | 若明显变大 ⇒ 收益可能被 I-cache 吃掉，需在 G-D 里解释 |

## 6. 判据优先级

1. **P0（作废条件）**：A 侧重建的 `.text` sha256 与冻结二进制不同 ⇒ 加 `/MAP` 改变了代码
   生成，A/B 不再可比，**实验作废**，改用不依赖 map 的替代方案（PDB + DbgHelp 解析）。
2. **P1（机制）**：C2/C4。机制不成立时，§3.1 的时间差不归因于内联。
3. **P2（收益）**：§4 的门。
4. **P3（旁证）**：二进制体积、8P 一致性。

## 附：为什么这个实验值得做，尽管预期收益只有 1.8%

因为它是整个 Stage F 里**唯一能把"采样观察"与"因果推论"分开**的实验。

F1 观察到 `Fp::mul` 在 prover 中以未内联形态出现（91.8% 的样本），并推论这带来 7.06 ns/次
的成本。F2 用计数证明这个推论被 ILP 掩盖了大半。H1c 实验是第三个独立检验：
**如果真的内联了，收益是多少？** 三者若一致，`Fp::mul` 这条线就可以彻底关掉，
Stage F3 才能心安理得地把全部预算投给 `Negated → Scale(−1)`。
