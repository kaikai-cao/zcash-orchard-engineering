# 14 · Stage H1c 预注册：只改 LTO，到底能拿回多少

> **本文件在任何测量之前写定。** 下面第 4 节的门槛、第 5 节的预测、第 6 节的判据，
> 都在看到 LTO 构建的任何数字之前固定。如果结果落在预测之外，结论要在第 7 节
> 如实记录为"预测失败"，而不是回头改门槛。

## 1. 要检验的假设

**H1c（F1 提出，F2 降级）**：prover 里 `Fp::mul` 的调用开销可以靠**编译配置**（跨 crate 内联）拿回来。

| 版本 | 收益估计 | 依据 |
|---|---:|---|
| F1 原始 | **10.6%** | 未内联延迟 21.73 ns × 假设每次乘法都付延迟 |
| F2 修正 | **≈1.8%** | 1.076 亿次 × (10.70 − 10.14) ns ≈ 0.06 s |

两者差 6 倍。F2 的修正建立在一个**可证伪的中间量**上：prover 中 `Fp::mul` 的真实均价
是 10.70 ns（由 1.076 亿次计数与 E3 的 1.155 s 相乘反推），只比全内联吞吐 10.14 ns
高 5.5%。如果这个中间量错了，H1c 的原始估计就重新成立。

所以本实验的真正目的**不是"看 LTO 能不能提速"**，而是**给 H1c 判死刑或复活**：

- 若实测收益 ≈ 1.8% ⇒ F2 的修正成立，H1c 关档；
- 若实测收益接近 10% ⇒ F2 的 10.70 ns 反推有问题，需要回头查计数口径；
- 若实测收益 ≈ 0 且**内联确实发生了** ⇒ 调用开销本来就几乎为零，H1c 彻底关档，
  且证明"未内联"这个观察与"有成本"这个推论之间没有因果。

第三种结果是**最有信息量的**，也是最可能的。

## 2. 单因子设计

只改一个设置：`lto`。其余全部从 `release` 继承，不改一行 Rust 源码。

```toml
[profile.release]          # 冻结基线（comparison 的 A 侧）
debug = false              # opt-level 3 / codegen-units 16 / panic unwind / 无 target-cpu

[profile.lto]              # 处置组（B 侧）
inherits = "release"
lto = "fat"                # ← 唯一变量
```

**明确不动的项**（用户要求，也写在 `harness/Cargo.toml` 注释里）：

| 项 | 值 | 为什么不动 |
|---|---|---|
| `codegen-units` | 16（默认继承） | 若同时降到 1，`lto` 与 CGU 的影响混在一起，单因子失效 |
| `target-cpu` | generic（不设 `RUSTFLAGS`） | F1 已证明 `+bmi2,+adx` 无收益，不应再引入第二个变量 |
| `opt-level` | 3 | — |
| `panic` | unwind | 改 abort 会改变代码布局 |
| `debug` | false（计时）/ true（采样，见 §3.3） | 采样必须两边都带 PDB 才能对等比较 |

**为什么用 `fat` 而不是 `thin`**：`fat` 是"跨 crate 内联"这个机制的上界，与 §1
"给假设判死刑或复活"的目的相匹配。若 `fat` 都拿不到收益，`thin` 不会更好，
不必再花一个构建。若 `fat` 拿到了收益但用户不愿承担构建时间，再单独测 `thin`。

**为什么需要重新构建 A 侧**：不是要换基线，而是为了

1. 拿到 `/MAP` 符号表（冻结的 `target/release/orchard-e2e.exe` 没有符号，
   MSVC 把符号放在外部 PDB 里，而本机没有 `llvm-pdbutil`/`dumpbin`），
2. 验证 `/MAP` 是**代码生成中性**的：A 侧重建后 `.text` 的 sha256 必须与冻结二进制一致。
   若不一致，说明加了链接参数后代码变了，B 侧的对比就不干净，实验作废（见 §6 判据 P0）。

## 3. 测量协议

### 3.1 交错 A/B，而不是先跑完 A 再跑 B

跨批次绝对值漂移在 F2 里已经实测到 **6.5%**（1559 vs 1681 ms），比 H1c 的全部预期
收益（1.8%）大 3.6 倍。若 A 全跑完再跑 B，测到的是机器热状态，不是 LTO。

因此：**同一会话内交替执行**，顺序固定为 `A B A B A B A B A B`（各 5 轮），
每轮内部 `--reps 5`，取每轮的 5 个 `prove_s` 样本，合计 **25 个样本/侧**。

| 参数 | 值 |
|---|---|
| 命令 | `--mode v3 --version v3 --spends 1 --outputs 2 --reps 5 --seed 7` |
| 主指标 | `orchard_prove_s`（2 个 action = 1 spend + 1 output，与 E1 基线同一口径） |
| 1P | `RAYON_NUM_THREADS=1`，`--mask 0x1` |
| 8P | `RAYON_NUM_THREADS=8`，`--mask 0xFF` |
| A 侧二进制 | `target/h1c-baseline/release/orchard-e2e.exe`（= 冻结二进制 + `/MAP`） |
| B 侧二进制 | `target/h1c-lto/release/orchard-e2e.exe` |
| 电源计划 / 提权 | 同 F0：balanced / 非管理员（与基线冻结时一致） |

### 3.2 统计口径

- 每侧 25 个 `prove_s`：报 **中位数**、均值、CV、与 A 侧中位数之比的差值；
- 差值的不确定性用**配对 bootstrap**（按"轮"重采样，5 对，10 000 次）给出 95% 区间，
  而不是假设正态；
- **不以单次跑赢 1% 作为结论**。1P 的 CV 是 1.86%，单轮差值落在噪声里就照实说。

### 3.3 内联验证（这是 H1c 的**机制**证据，缺了它整个实验只是"改了个开关"）

| 检查 | 做法 | 期望 |
|---|---|---|
| C1 | A/B 两侧都用 `-C link-arg=/MAP:<file>` 链接，从 map 中取 `evaluate::recurse` 的 RVA 与长度 | 符号存在且可定位 |
| C2 | `objdump -d` 反汇编 A/B 二进制，切出 `recurse` 函数体，数其中 `call` 指令的条数与目标 | A：`recurse` 体内有 `call` 指向 `Fp` 乘法符号；B：同位置**不再有**该调用 |
| C3 | 全二进制统计"调用 `Fp` 乘法的 `call` 条数" | B 显著少于 A（不一定为 0：其他调用者仍可能存在） |
| C4 | E3 采样（`--mode profile --e3-out ... --e3-interval-ms 4`，`target/sampling` vs `target/lto-sampling`） | `Fp::mul` 作为**叶子帧**出现的样本数大幅下降，`evaluate::recurse` 的 self 份额相应上升（时间不会消失，只是换了归属） |

C4 的预期是本文件最容易被打脸的一条：如果 B 侧 `Fp::mul` 的 self 占比**没变**，
说明 LTO 根本没内联它，那么无论 §3.1 测出什么，H1c 的机制都不成立。

## 4. 决策门槛（先定，后测）

以 1P 的配对差值 `Δ = (median_B − median_A) / median_A` 为准（负值 = 变快）。
8P 只作旁证：8P 的 CV 更小（1.05%）但核间干扰更大，不单独作为判据。

| 门 | 条件 | 结论 | 后续动作 |
|---|---|---|---|
| **G-A** | `Δ ≤ −5%` | F2 修正被推翻，H1c 复活 | 回头查 10.70 ns 反推（计数口径/采样分母），并把 LTO 列入发布配置 |
| **G-B** | `−5% < Δ ≤ −1%` 且 95% 区间不跨 0 | 收益真实，与 F2 的量级相容 | 记录数值，作为"可选发布配置"，不进 F3 主线 |
| **G-C** | `\|Δ\| < 1%` 或区间跨 0 | **无可测收益** | H1c 关档（结论：调用开销已被 ILP 掩盖，inline 与否不影响吞吐），F2 的 1.8% 上限未被违反 |
| **G-D** | `Δ ≥ +1%` | LTO 有害（代码膨胀 / I-cache） | 记录并关档 |

**无论哪个门命中，都要报一件事**：Δ 的 95% 区间上界是多少。若上界 < 10.6%，
F1 的 10.6% 在统计上被证伪——这是本实验**必定**能交付的结论，比"省了几个百分点"更重要。

## 5. 事前预测（可打脸）

| 项 | 预测 | 若不符 |
|---|---|---|
| 1P `Δ` | **−0.5% ~ −2.5%**，中位约 **−1.5%** | 见 §4 |
| 8P `Δ` | 与 1P 同向、同量级（LTO 不改变并行结构） | 说明 8P 的行为另有原因，需查 |
| C2：`recurse` 体内对 `Fp` 乘法的 `call` | A ≥ 1 条，**B = 0 条** | B 仍 > 0 ⇒ LTO 未内联该函数 ⇒ H1c 机制不成立 |
| C4：`Fp::mul` 叶子帧样本 | B 比 A 少 **≥ 80%** | 少 < 50% ⇒ 内联只发生了一部分，与 C2 交叉核对 |
| 二进制体积 | B 比 A **小**（消除重复单态化） | 若明显变大 ⇒ 收益可能被 I-cache 吃掉，需在 G-D 里解释 |

## 6. 判据优先级

1. **P0（作废条件）**：A 侧重建的 `.text` sha256 与冻结二进制不同 ⇒ 加 `/MAP` 改变了代码
   生成，A/B 不再可比，**实验作废**，改用不依赖 map 的替代方案（PDB + DbgHelp 解析）。
2. **P1（机制）**：C2/C4。机制不成立时，§3.1 的时间差不归因于内联。
3. **P2（收益）**：§4 的门。
4. **P3（旁证）**：二进制体积、8P 一致性。

## 7. 结果（测量后填写）

### 7.0 先说结论

**H1c 关档，但理由不是"收益小"，而是"这个机制在编译配置层面根本不存在"。**

`lto = "fat"` 没有把 `Fp::mul` 内联进 `evaluate_inner::recurse`。反汇编显示两侧
`recurse` 函数体内对 `Fp::mul` 的 `call` 条数**完全一样**（合计 9 条），采样显示
`Fp::mul` 作为叶子帧的自占比**没有变化**（36.67% → 36.49%），端到端计时也就没有变化
（1P：+0.00%，95% 区间 [−1.57%, +1.14%]）。

于是 §5 的两条机制预测（C2 = 0 条调用、C4 减少 ≥80%）**都失败了**，而且失败得很有信息量：
`#[inline]` 是提示不是命令，LLVM 的成本模型不会因为跨 crate 可见、或者因为 LTO
就把一个约 200 条指令的函数塞进循环体。`pasta_curves` 甚至专门提供 `uninline-portable`
feature 来**关掉**这个提示，说明上游自己知道这一点。

`Fp::mul` 这条线可以彻底关掉了：不是"还没试 LTO"，而是"LTO 试过了，它动不了这个决定"。

### 7.1 计时（1P 是判据，8P 是旁证）

交错执行 A B A B …，各 5 轮 × 每轮 `--reps 5` = 每侧 25 个 `prove_s` 样本。

| 配置 | 中位 | 均值 | CV | 相对 A |
|---|---:|---:|---:|---:|
| 1P A（release） | 3106.6 ms | 3179.2 ms | 3.84% | — |
| 1P B（release + lto=fat） | 3141.2 ms | 3192.2 ms | 3.43% | **+1.11%** |
| 8P A | 859.0 ms | 867.2 ms | 4.43% | — |
| 8P B | 870.1 ms | 872.0 ms | 2.61% | **+1.29%** |

逐轮（每轮 5 次的样本中位数）：

| 轮 | 1P A | 1P B | Δ | 8P A | 8P B | Δ |
|---|---:|---:|---:|---:|---:|---:|
| r1 | 3310.1 | 3294.6 | −0.47% | 833.0 | 845.5 | +1.50% |
| r2 | 3244.0 | 3149.3 | −2.92% | 845.8 | 858.1 | +1.45% |
| r3 | 3105.0 | 3134.0 | +0.93% | 877.8 | 879.5 | +0.19% |
| r4 | 3090.9 | 3122.0 | +1.01% | 886.8 | 907.5 | +2.34% |
| r5 | 3091.8 | 3134.5 | +1.38% | 879.1 | 881.0 | +0.22% |

配对 bootstrap（按轮重采样，10 000 次）：

| | 平均 Δ | 95% 区间 | 命中的门 |
|---|---:|---|---|
| 1P | **+0.00%** | **[−1.57%, +1.14%]** | **G-C 无可测收益** |
| 8P | **+1.14%** | **[+0.45%, +1.83%]** | G-D（LTO 反而略慢） |

注意前两轮 1P 的 A 是 3310/3244 ms，后三轮掉到 3090 ms —— 这正是 §3.1 说的热状态漂移
（同一二进制、同一会话，前 10 分钟和后 10 分钟差 6.5%）。**交错执行仍然必要**，
但它也不能消除"轮内先 A 后 B"的固定顺序偏差；8P 的 +1.14% 很可能就是这个偏差
（8P 单次只有 0.87 s，前一轮的尾巴更容易落进后一轮）。所以 8P 只作旁证。

**已交付的那条硬结论**：1P 的 95% 区间上界是 **+1.14%**，即数据在 95% 置信下
**排除了 10.6% 的收益**。F1 的 10.6% 在统计上被证伪，F2 的 ≈1.8% 上限未被违反
（区间上界 1.14% < 1.8%，也相容于"上限约 1.8%、实测约 0"）。

### 7.2 机制 1：反汇编（预测 C2 失败）

两侧都用 `/MAP` 链接，从 map 取 `evaluate_inner::recurse` 的地址区间，
用 `objdump -d` 切出函数体，再回 map 查每个 `call` 的目标：

| | A（release） | B（lto=fat） |
|---|---:|---:|
| `recurse` 单态化个数 | 2 | 2 |
| 函数体大小 | 2288 B / 2752 B | 2112 B / 2272 B |
| 函数体内 `call` 总数 | 22 / 33 | 28 / 31 |
| **其中调用 `Fp::mul`** | **5 / 4（合计 9）** | **4 / 5（合计 9）** |
| 其中调用自身（递归） | 6 / 6 | 6 / 6 |
| 全二进制 `Fp::mul` 的独立入口 | 1 个地址、14 个 COMDAT 别名 | 1 个地址、1 个别名 |

**9 → 9，一条都没少。** 预测 C2 要求 B 侧为 0，实际完全没变。

顺带得到的两个细节：

- `Fp::mul` 在 A 侧被 ICF 折成**一个**地址（14 个 `.llvm.*` 别名指向同一处），
  B 侧只剩一个别名 —— 说明 LTO 确实合并了重复单态化，只是没有内联。
- B 侧函数体反而**小了一点**（2288 → 2112 B），但 `call` 更多 —— 这是典型的
  "把调用者的寄存器压力交给被调者"的结果，与"内联"相反。

`Fp::mul` 的源码标注是 `#[cfg_attr(not(feature = "uninline-portable"), inline)]`
（`pasta_curves-0.6.0/src/fields/fp.rs:366`）—— **`inline` 是提示**。
`mul` + `mul_unreduced` + `montgomery_reduce` 全展开后约 200 条指令，
LLVM 把一个这样的函数内联进热循环会显著放大代码体积，成本模型因此拒绝。
LTO 只解决"跨 crate 看不看得见"，不解决"该不该内联"。

### 7.3 机制 2：采样（预测 C4 失败）

同源两侧（都带 debug info，唯一差异是 LTO），1P，`--reps 6`，4 ms 节拍：

| 函数 | A busy self | B busy self |
|---|---:|---:|
| `pasta_curves::fields::fp::Fp::mul` | **36.67%** | **36.49%** |
| `evaluate_inner::recurse<…>` | 14.83% | 12.78% |
| `subtle::black_box<u8>` | 14.83% | 12.37% |

预测 C4 要求 `Fp::mul` 的叶子帧样本减少 ≥80%，实际 **−0.18 个百分点**（噪声内）。
三条独立证据（反汇编、采样、端到端计时）指向同一件事，这比任何单条都可靠。

> 这里的 36.5% 与 E3 文档里的 33.08% 不可直接比较：E3 的分母是整个证明窗口，
> 这次的分母只有 `--mode profile` 的证明循环窗口，且只有 6 次证明。
> 只在 A/B 之间比。

### 7.4 与预注册的偏离（必须记录）

| 预注册 | 实际 | 原因 |
|---|---|---|
| **P0**：A 侧重建的 `.text` 与冻结二进制的 sha256 一致 | **做不到** | 冻结二进制 `7df728f7…` 来自 F2 之前的源码；F2 往 vendor 里加了 `f2.rs` 与 5 处插桩，重建必然不同（3.106 MB → 3.360 MB）。**P0 的本意是验证 `/MAP` 是否改变代码生成**，这一条改用同源两次构建来测：同一份源码，一次带 `/MAP`、一次不带，`.text` 的 sha256 都是 `8d5ca96d…`（3 360 328 B），**完全相同** ⇒ `/MAP` 代码生成中性成立 |
| A 侧 = 冻结二进制 | A 侧 = 同源重建（release） | 同上；且单因子要求 A/B 同源。冻结值仅作量级参照 |
| 未预定第三个采样对照 | 额外构建了同源 `sampling`（非 LTO） | 原计划拿 F2 之前的 `target/sampling` 作对照，但那会混入"源码变了"这个第二因素 |
| 未预定构建耗时记录 | 已补：A 51 s / B 1 m 30 s / C 2 m 09 s / D 53 s | LTO 让构建慢 40 s，换回 0% |

**同会话的绝对值比 F0 基线低约 7%**（1P 中位 3106.6 vs 冻结 3351.1 ms；8P 859.0 vs 928.3 ms）。
这是机器状态差异，不是代码变化 —— 也正因如此，本次**一个跨会话比较都没做**，
7.1 的所有数字都来自同一会话内交错的 A/B。

### 7.5 对假设登记表的更新

| 假设 | 原状态 | 新状态 |
|---|---|---|
| **H1c** 消除 `Fp::mul` 调用开销（LTO/内联） | F2 后："降级：收益依据不成立，上限 ≈1.8%" | **关档**：`lto=fat` 不影响内联决定（调用点 9→9，叶子帧 36.67%→36.49%），端到端 +0.00% [−1.57, +1.14]%；10.6% 在 95% 置信下被排除。要真正内联只能改依赖源码加 `#[inline(always)]`，那已不是"编译配置"路线，且 F2 已算出即便内联上限也只有 ≈1.8% |

F1 的"未内联观察"仍然成立（反汇编再次确认 9 个调用点），但**"未内联 ⇒ 有成本"这个推论
现在有两条独立的否定证据**：F2 的均价反推（10.70 ns 仅比内联吞吐高 5.5%），
以及本次的"就算 LTO 也内联不了，而端到端毫无变化"。

## 附：为什么这个实验值得做，尽管预期收益只有 1.8%

因为它是整个 Stage F 里**唯一能把"采样观察"与"因果推论"分开**的实验。

F1 观察到 `Fp::mul` 在 prover 中以未内联形态出现（91.8% 的样本），并推论这带来 7.06 ns/次
的成本。F2 用计数证明这个推论被 ILP 掩盖了大半。H1c 实验是第三个独立检验：
**如果真的内联了，收益是多少？** 三者若一致，`Fp::mul` 这条线就可以彻底关掉，
Stage F3 才能心安理得地把全部预算投给 `Negated → Scale(−1)`。
