## 1. 研究问题

F4-A 的 −22.00%（1P）是在**一个固定配置**上测出来的：Orchard V3，1 spend + 1 change，
2 个 action。它没有回答一个更基础的问题：

> 这项收益是随 action 数量增长、保持不变，还是只在当前两 action 配置下才明显？

必须区分三种可能的形状，因为它们对应三种完全不同的机制解释：

| 形状 | `ΔT(n)/n` | 机制解释 | 后续含义 |
|---|---|---|---|
| 恒定 | 常数 | 每个 action 内部就有等量的重复恢复链；跨 action 只是把同一件事再做一遍 | 收益是**每 action 的结构性质**，与规模无关 |
| 增长 | 上升 | memo 的填充成本被更多消费者摊销，且跨 action 的链被合并到同一 slot | 收益是**规模的函数**，大 bundle 才是主战场 |
| 下降 | 下降 | 复用受执行上下文限制，或固定开销占比上升 | 当前 22% 可能是小配置的巧合，需重新界定适用范围 |

**本阶段只回答形状，不回答"Halo2 通用性"。** 后者（换一个同样有 selector compression
恢复链的电路）是下一阶段，见 §7。

## 2. 为什么用 action 数量做标度变量

`prover.rs` 的表达式展开是 `advice_cosets.iter().flat_map(...)`：**每个 action 一份**。
所以 action 数量直接控制"同一批恢复链被重复计算多少遍"，而**不改变**：

- 电路版本（`PostNu6_3`）与 `configure()` 产生的门表；
- 选择器压缩的结果（固定列与 `compress_selectors` 的输出）；
- 证明域大小 K。

换句话说，n 是本实验里唯一被改变的变量，而它改的正是 F4-A 要消除的那种重复。
这比"换一个电路"更干净：换电路会同时改门表、K、selector 集合，收益变化无法归因。

## 3. 可构造的 n（构造可行性已先行验证）

Orchard 的电路是**每 action 一个 `Circuit` 实例**，`create_proof` 接收实例切片，
K 由单 action 的电路形状决定，与实例数无关。两个 NU6.3 池对"花多少 action"的算法不同：

```
cross-address 关闭（orchard_v3）：actions = spends + outputs
cross-address 开放（ironwood_v3）：actions = max(spends, outputs)
```

因此：

| 池 | 可得的 n | 构造 | flags |
|---|---|---|---|
| `ironwood_v3` | **1, 2, 4, 8** | n spends + n plain outputs，全部同一地址 | spends ✅ outputs ✅ cross-address ✅ |
| `orchard_v3` | **2, 4, 8** | n/2 spends + n/2 change outputs | spends ✅ outputs ✅ cross-address ❌ |

`orchard_v3` 拿不到 n=1：cross-address 关闭时每个 spend 必须与一个独立 action 的
fabricated output 配对，1 spend 就已经是 2 个 action。**这个"拿不到"是协议性质，不是实现缺陷**，
所以 n=1 只有 ironwood 一个点。

**两个池的 flags 不同，但电路相同。** `PostNu6_3` 的 cross-address 约束由 instance 里的
flag 值启用，不是额外的门；两池共用同一 `OrchardCircuitVersion`。所以：

- 同一池内，n 是唯一变量；
- 跨池比较**不是**同一实验（flags 不同），只作为"同一 n 下两条独立曲线是否给出一致形状"的交叉检验；
- 两条曲线在任何报告里都分开画，不拟合成一条。

**K 的固定性**：每个进程只调用一次 `ProvingKey::build(PostNu6_3)`，所有 n 复用同一
`pk`/`vk`。K 因此按构造相同——不是"测出来相同"，而是"只可能相同"。

### 3.1 fixture

`notes_at_leaves`：把 `k` 个 note 放在同一棵树的叶子 `0..k`，一次性建出各层子树根，
每个叶子的认证路径取 `(i >> l) ^ 1` 位置的兄弟根（空侧取空子树根），并在构造后断言
所有路径根到同一 anchor。这是上游 builder 测试里 shared-anchor witness 的同一套构造。

- 每个 spend note 100 000 000，每个 output/change 85 000 000；
- n 个 action 的价值平衡 = 15 000 000 × n（对 `i64` 与 `MAX_MONEY` 都安全）；
- 每个 note 的 `rho`/`rseed` 独立抽取，nullifier 互不相同。

**这不是填充电路**：n 个 action 花的是 n 个真实存在的 note，走的是同一条生产代码路径。

### 4.2 预测（A）

| # | 预测 | 判据 | 若失败的读法 |
|---|---|---|---|
| **A1** | 收益随 n **稳定或增长**：`ΔT(n)/n` 在 n=2,4,8 上的（极差 / 均值）**≤ 20%** | 实测 | 若 >20% 且单调下降 ⇒ 判为"规模不友好"，必须归因到固定开销或上下文限制 |
| **A2** | 收益位置不变：每个 (pool, n) 的 `Δquotient / Δprove ≥ 0.90` | 实测 | 若某 n 掉到 0.90 以下 ⇒ 说明该规模下有别的阶段被牵连，A1 的解释不成立 |
| **A3** | 比值单调不增：ironwood 的 `B/A` 中位数在 n=1→2→4→8 上非递增（容差 0.01） | 实测 | 若中途回升 ⇒ 摊销假设错误，memo 的固定成本没有被摊薄 |
| **A4** | memo 驻留**不随 n 变化**：每个池的 `memo_bytes` 在各 n 之间相对偏差 ≤ 5% | 实测 | 若随 n 增长 ⇒ 每个 action 的链被分配了独立槽位，跨 action 没有合并 |
| **A5** | memo 读取**随 n 线性**：`memo_reads / n` 的相对极差 ≤ 15% | 实测 | 若偏离 ⇒ 跨 action 的链不是同一批，收益的"重复度"随 n 变化 |
| **A6** | 分配次数的减少**随 n 线性**：`Δalloc_calls(n) / n` 的相对极差 ≤ 25% | 实测 | 若偏离 ⇒ `Val` 的就地折叠在不同 action 数下行为不同（doc 25 §11 的模型需要再修一次） |
| **A7** | 被消除的乘法**随 n 线性**：`structural_mul_eliminations(n) / n` 的相对极差 ≤ 15% | 实测 | 若偏离 ⇒ `intern_chains` 的 `occ ≥ 2` 判定在 n 增大时合并了更多链，收益曲线会超线性（不是坏事，但必须说明） |

## 6. 分析口径

主量：

```
ΔT(n)      = median over pairs of [ T_A(n) − T_B(n) ]
ΔT(n)/n    = ΔT(n) / n
ratio(n)   = median over pairs of [ T_B(n) / T_A(n) ]
```

- 差值用**逐对相减**后的中位数，不用"两个中位数相减"；
- 比值用逐对比值的中位数，配 10 000 次 bootstrap 的 95% CI；
- 方向一致性用符号检验（多少对 B<A）；
- `ΔT(n)/n` 的稳定性用（极差 / 均值）判定，不用回归斜率——n 只有三个点，斜率没有意义。

阶段：`Δstage(n) = median_pairs [ stage_A − stage_B ]`，并要求 `Σ Δstage` 与 `ΔT` 的差
在 1% 以内（G3）。

## 7. 本阶段回答什么、不回答什么

**能回答**：

- F4-A 在 Orchard V3 的 1–8 action 范围内，`ΔT(n)` 与 `ΔT(n)/n` 的形状；
- 这种形状是否与"电路决定链的种类、action 数决定读取次数"的机制解释一致；
- 资源代价（memo 驻留、分配）是否随 n 出现非线性。

**不能回答**：

- F4-A 是否是 Halo2 的通用优化。本实验只有一个电路、两个 flags 组合；
- 跨电路是否也能受益。需要另立一项：选一个同样由 selector compression 产生
  `q·∏(r_i − q)` 结构的 Halo2 电路，检查同一机制能否复用；
- n 更大（16、32）时的行为。本阶段只到 8，且 8 已使单次证明超过 10 s（1P）。

**结论措辞的上限**：即使 A1–A7 全过，只能说
"F4-A 在 Orchard V3 的 action 规模上具有稳定的每 action 收益"，**不能**说"通用"。

## 10. 一句话

**收益随 action 数超线性增长，而不是保持恒定**：1P 的 `ΔT(n)/ΔT(1)` 在 n=2/4/8 上是
**2.48× / 5.41× / 11.52×**，即每 action 收益从 277.9 ms 升到 400.2 ms；`B/A` 从 0.8565
单调降到 0.7157。位置始终在 `quotient`（份额 95.5%–102.8%），代价始终只有一份 memo
（`slots` 在 n≥2 时恒为 49，每 chunk 6.125 MiB）。**n=1 是唯一的边界点**：它拿不到跨 action
的共享（`slots` 38 而非 49），但仍拿到 −14.35%。

## 11. 主曲线

### 11.0 表里三种统计量的口径（读表前必看）

主表的三列不是同一个统计量，**不能互相加减乘除**：

| 列 | 定义 | 怎么算的 |
|---|---|---|
| `A` / `B` | **边际中位数**（marginal median） | 把 20 次 A 臂运行的时间单独排序取中位；B 臂同理 |
| `ΔT` | **配对差值中位数**（paired difference） | 先对每一对算 `A_i − B_i`，再对这 20 个差值取中位 |
| `B/A` | **配对比率中位数**（paired ratio） | 先对每一对算 `B_i / A_i`，再对这 20 个比值取中位 |

因此 `A 中位 − B 中位 ≠ ΔT 中位`。例如 n=8 的 ironwood：

```
11296.9 − 8045.6 = 3251.3 ms      （两个边际中位数之差）
ΔT 中位          = 3201.2 ms      （每对差值的样本中位）
```

差 50.1 ms（1.5%）。这不是矛盾：`median(A) − median(B)` 与
`median(A − B)` 在 A、B 相关时一般不相等，而同一进程内的配对本来就是强相关的。
**本报告所有性能结论都用 `ΔT` 与 `B/A` 这两个配对统计量；`A`/`B` 两列只用于
展示量级。** 同理 `ΔT/n` 是"配对差值中位 ÷ n"，不是"边际中位之差 ÷ n"。

## 13. 结构计数：为什么是超线性

| n | chains | slots | root 消费者 | chain_muls | structural_mul_eliminations | 每 action 消除 | memo_reads（1P/8P） |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 50 | **38** | 180 | 870 | **624** | 624.0 | 1 344 / 10 752 |
| 2 | 51 | **49** | 360 | 1 740 | **1 487** | 743.5 | 2 864 / 22 912 |
| 4 | 53 | **49** | 720 | 3 480 | **3 213** | 803.3 | 5 728 / 45 824 |
| 8 | 57 | **49** | 1 440 | 6 960 | **6 665** | 833.1 | 11 456 / 91 648 |

三列的分工很清楚：

- **`chain_muls` 与 `root 消费者` 严格线性**（870/180 每 action）。被重复计算的"基线工作量"
  就是与 n 成正比的，没有别的成分。
- **`slots` 在 n≥2 时恒为 49**：共享链的**种类**由电路决定，与 n 无关。
  memo 的填充成本因此是**每 chunk 一次、与 n 无关**。
- **`structural_mul_eliminations` 略超线性**（624 → 1 487 → 3 213 → 6 665，相邻比值
  2.38× / 2.16× / 2.07×）。原因是 `saved = Σ(occ−1)(k−1)` 对 occ 不是线性的：
  当同一槽的消费者数从 2 增到 4，`(occ−1)` 从 1 增到 3，是 3 倍而不是 2 倍。
  **基线要重算全部 occ 份，而 B 臂只填一次**，所以 n 越大，省下的越多。

n=1 那个点必须单独读：**`slots` 是 38 而不是 49**。缺的 11 条链不是"没被识别"，而是
**跨 action 才出现的重复**——它们在 n=1 时本来就只出现一次，按 `occ ≥ 2` 的规则不该分配槽位
（V6）。这给出一个干净的分解：

| 共享来源 | 证据 | 1P 贡献 |
|---|---|---|
| action 内部（同一约束系统的不同消费者） | n=1 就有 **38 槽 / 624 次消除** | 约 **278 ms / action**（n=1 的全部收益） |
| action 之间（不同实例的对应位置复用同一槽） | 38 → **49 槽**，624 → 743.5 次/action | 再补约 **66–120 ms / action** |

`memo_reads` 与 n 严格线性（1P：1 432/action；8P：11 456/action = 1P 的 8 倍，正好是 chunk 数
4 → 32 的比）。**同一批槽被读更多次**——这是"填充一次、读取 n 次"的直接读数。

### 15.1 三条 FAIL 全部来自 n=1 这一个端点

按预注册，判据不改。但把 ironwood 的 **n≥2 子集**单独算一遍就能看清失败的性质：

| 判据 | 范围 | 相对极差 | 结论 |
|---|---|---:|---|
| A4 | 1P / 8P ironwood n≥2 | 0.0% / 0.0% | PASS |

n=1 之所以是端点，是因为它**没有跨 action 的重复**（§13：`slots` 38 而非 49），

于是把端点算了进去。**下一份预注册应当把"端点"与"标度区"分开定义**，本节不重算判据。

### 15.2 G2 失败的含义

`orchard n=2` 的 1P A 中位是 3 253.9 ms，比 doc 25 的 3 734.9 ms 低 12.9%，
落在预注册区间 [3 400, 4 100] 之外。但：

- 该配置的 proof 指纹与 doc 24 的 80 次计时证明**逐位相同**（`0xa6bcd171d69e969a`），
  bundle 输入与噪声没有变化；
- 同一进程内的 `n=1 → n=8` 曲线自洽（`ΔT(n)/ΔT(1)` 与 `structural` 的斜率一致）；
- rustc 仍是 1.98.1，绑核仍是 0x1，E2 计时仍开。

因此差异只能落在**跨批次的机器状态**（后台负载、频率、分配器页状态）。这条正是预注册 §5
边界 3 已经写下的担忧，现在被实测确认：**同一个二进制、同一份 fixture，两周内的绝对中位数
也会漂 13%。** 按预注册，本次不使用任何跨批次绝对毫秒；G2 只用来标记"这批不能与 doc 25 并列"，
不影响 A1–A3（全部是同会话配对量）。

## 16. 结论

1. **形状是"超线性"，不是"恒定"。** 1P 的 `ΔT(n)/ΔT(1)` 在 n=2/4/8 上是 2.48× / 5.41× / 11.52×，
   每 action 收益 277.9 → 400.2 ms；`B/A` 单调 0.8565 → 0.7157（−14.35% → −28.43%）。
   8P 同形（0.8720 → 0.7675，−12.80% → −23.25%），幅度小 5 个百分点。
2. **机制解释有三处独立支撑**：`slots` 在 n≥2 恒为 49（种类由电路定）、`memo_reads` 严格
   线性（读次数由 n 定）、`structural` 略超线性（`(occ−1)` 对 occ 非线性）。
   三者与 `ΔT` 的形状一致，不是同一个数字的三种说法。
3. **收益位置不变**：`quotient` 承担 95.5%–102.8%，八个非 quotient 阶段的偏移随 n 放大但
   始终 ≤ 0.1% 相对量。**F4-A 没有把工作推给别的阶段，也没有在放大规模时改变作用点。**
4. **代价不随 n 失控**：memo 每 chunk 恒定 6.125 MiB（1P）/ 0.766 MiB（8P），
   分配字节的 `B/A` 稳定在 0.50–0.63。绝对内存随 n 增长是证明本身变大，不是共享机制的代价。
5. **n=1 是端点**：它拿不到跨 action 复用（38 槽而非 49），仍得 −14.35%。
   **这恰好把 F4-A 的收益拆成两半**：action 内 ≈ 278 ms / action，action 间再补 ≈ 66–120 ms / action。
6. **措辞上限**：以上只说明"F4-A 在 Orchard V3 的 1–8 action 范围内有稳定的每 action 收益，
   且随规模略增"。**不能**据此说 F4-A 是 Halo2 的通用优化——本实验只有一个电路、
   两个 flags 组合。跨电路验证是下一阶段（§7）。

## 18. F4-A 的三条独立结论

这份定稿的主要目的，是把 F4-A 拆成三条**互不依赖**的结论。它们回答三个不同层次的问题，
证据类型不同、失效条件也不同；任何一条不成立，另外两条仍然可以成立。

### 18.1 结论 A · 机制发现（与是否采用 F4-A 无关）

> **Halo2 的 selector 压缩在 keygen 阶段生成形如 `q·∏(i−q)` 的替换表达式；当门的次数没有顶满
> `ConstraintSystem` 的 degree 预算时，该子表达式会在约束求值树中以相同形状重复出现；
> 重复的份数由"同一 selector 被同一门的多条约束引用"决定。**

- **归属**：由 `halo2_proofs::plonk::circuit::compress_selectors` 生成，
  `keygen.rs` 在每条 keygen 路径上无条件调用。不是 Orchard 手写，也不需要电路作者知情（doc 27 §1）。
- **可判定**：`d_s ≤ D−1` 可以先算后测（doc 27 §6）。
- **单因子证据**：同一份 Poseidon 电路，只把 CS degree 从 5 抬到 9，链从 **0 → 3**
  （消费者 10 个、`saved = 14`）。degree 是本轮唯一被隔离的变量（doc 27 §5.3）。
- **量纲**：`saved = Σ(occ−1)(k−1)`；Poseidon `hi` 的 14 与手算 `2×(10−3)` 逐位相等。

这条结论**不依赖 F4-A 是否被实现**：即使从不优化，库仍然每次 keygen 都造出这些重复子式，
基线每次求值仍然要把 `occ` 份全算一遍（Orchard 单实例 `occ_muls = 869`）。

### 18.2 结论 B · 实现优化（只在 Orchard V3 / `PostNu6_3` 上成立）

> **把重复链换成每 chunk 预计算一次的只读 memo，在 Orchard V3 上 1P 完整 Prove −22.00%、
> 8P −15.27%；proof 与 `h` 系数逐位不变；内存代价 +6.1 / +6.7 MiB，分配 −8 617 次 / −1.60 GiB。**

| 量 | 1P | 8P | 出处 |
|---|---|---|---|
| 完整 Prove | **−22.00%**（CI [−23.24, −21.38]，19/20，p=4.0e−5） | **−15.27%**（20/20，p=1.9e−6） | doc 24 §5 |
| 正确性 | 7264 B / `0xa6bcd171d69e969a` / `h` FNV `0xee5d0c5e768ae539` | 同 | doc 24 §3.3 |
| 收益位置 | `quotient` 承担 **100.4%** | **101.2%** | doc 25 §9.4 |
| 内存代价 | 采样峰值 **+6.09 MiB**；memo 6.125 MiB/chunk | **+6.72 MiB**；0.766 MiB/chunk | doc 25 §9.2 |
| 分配代价 | **−8 617 次（−8.9%）/ −1.603 GiB（−44.5%）** | **−100 512 次（−33.4%）/ 同一 −1.603 GiB** | doc 25 §9.3 |

**适用范围写死在标题里**：一个电路（Orchard V3）、一个版本（`PostNu6_3`）、两个 flags 组合
（`orchard_v3` / `ironwood_v3`）。它不会因为结论 A 成立而自动扩张。

### 18.3 结论 C · 适用边界（内部标度 + 跨电路）

> **收益随 action 数超线性增长（1P：2.48× / 5.41× / 11.52×，每 action 277.9 → 400.2 ms），
> 而代价（memo 驻留）与 action 数无关；跨电路的机制存在性不等于收益：Poseidon 的 `saved`
> 只有 Orchard 的 2.3%，按 X5 判定不移植。**

内部标度（n = 1/2/4/8）：

- `B/A` **0.8565 → 0.7868 → 0.7427 → 0.7157**（−14.35% → −28.43%）；8P 同形，幅度小 5 个百分点；
- `slots` 在 **n ≥ 2 恒为 49**，memo **6.125 MiB/chunk** 不随 n 变，`memo_reads` 严格线性；
- **n = 1 是端点**：`slots = 38`，拿不到跨 action 复用，仍有 −14.35%。

跨电路（第二电路 = Poseidon-only）：

- 机制**存在**：`hi` 3 链 / 10 消费者 / 100% 根位置 / `saved = 14`；
- 收益**不普遍**：14 vs 621，**44 倍**；X5 FAIL ⇒ 不移植。

**判据是必要条件，不是充分条件**（doc 27 §6）：

| # | 条件 | 性质 | 本阶段验证程度 |
|---|---|---|---|
| C1 | `d_s ≤ D−1` | 链存在的必要条件 | 已验证（单因子翻转 0 → 3） |
| C2 | `occ ≥ 2` | 有节省的必要条件 | 已验证（结构计数） |
| C3 | 消费者在约束根、且可只读复用 | 有收益的必要条件 | **只验证了"位置"（10/10），未验证"复用后确有收益"** |

C3 这一格必须留在"未验证"里：**链存在与链可安全复用是两个问题**，本轮只回答了其中一半。

doc 27 §2 的五个筛选条件在这里收敛成三条：条件 1（同一份压缩实现）与条件 5（能独立
prove/verify）是**环境前提**，本轮两个候选都满足或已被排除；条件 2、3、4 就是 C1、C2、C3。
因此"筛选条件完整"的含义是：**环境前提 + 三条结构条件**，其中前两条已验证、第三条只验证了位置。

- **E1 直接证据**：源码级事实（可指到具体文件与调用点），或同会话配对的测量（有原始日志、CI 或全样本计数）。
- **E2 派生计算**：由 E1 的数字做算术或恒等式，可手算复核，但本身不是独立观测。
- **E3 机制推断**：由源码与结构计数支持，未做端到端验证；可能成立，但不可当作已测事实。

## 20. 未覆盖范围

本节是 doc 27 §3 那张表的定稿读法（两处口径已对齐）。ECC 与 Sinsemilla 不是"待验证的候选"，
而是**未覆盖范围**：既没有被测过，也没有被证伪；在本研究里不产生任何结论，也不计入样本量。

| 项 | 状态 | 原因 | 要覆盖需要什么 |
|---|---|---|---|
| `halo2_gadgets` ECC chip | **未覆盖（非候选）** | `OrchardFixedBases` 是私有模块，`GeneratorTableConfig` 为 `pub(crate)` | 自建 `FixedPoints` 窗口表（数百行）或改上游可见性；均超出只读范围 |
| `halo2_gadgets` Sinsemilla chip | **未覆盖（非候选）** | 同上，依赖 `FixedPoints` | 同上 |
| 外部生产电路（zkEVM、halo2-lib 等） | **不可及** | 本机没有可构建的第二份 halo2 工程 | 拉外部仓库 + 新构建环境（本轮明确不做） |
| 第二电路的端到端 A/B | **未做** | X5 FAIL 后按决定不移植 | 先有一个 `saved` 与 Orchard 同量级的电路 |
| C3 的复用可行性 | **未验证** | 只测了消费者位置比例 | 在 `hi` 变体上实现一次只读复用并计时 |
| n = 16 / 32 | **未测** | 8 action 的 1P 单次证明已 11.3 s | 更长的采样窗口 |
| 8P `n=8` 的内存 CI | **未算** | 诊断批次只有 3 对 | 加到 ≥ 10 对 |
| 峰值比 memo 多出的 2.2 MiB | **未定位** | 只给了候选解释 | 分配点级采样 |
| 跨批次绝对毫秒 | **不可比** | G2 已证漂 13% | 不能靠加样本解决 |

**样本量必须如实写成 2**：一个真实电路（Orchard）+ 一个合成对照（Poseidon `hi`）。
`hi` 是为隔离 degree 人为构造的门，不是任何生产电路。任何"N 个电路"的说法都不能把
`base` 与 `hi` 算成两个。

## 21. 措辞

### 21.1 可以说

1. selector 恢复链由 Halo2 库侧的压缩逻辑产生，不是 Orchard 手写（M-1）。
2. degree 预算是链能否出现的结构条件，且可先验判定（M-2）。
3. Orchard 的收益来自其特定结构：重复链数量、`occ`、消费者位置共同作用（M-4、I-1）。
4. 在当前证据下，F4-A 的跨电路通用性**尚未验证**；已能验证的是适用条件可先验判定（S-6、U-1）。

### 21.2 不能说

| 禁止措辞 | 为什么不成立 |
|---|---|
| "所有满足 `d_s ≤ D−1` 的电路都能获益" | C1 只是**必要**条件；还要 `occ ≥ 2` 与规模。Poseidon `hi` 三条全中也只省 14 个乘 |
| "所有 selector 恢复链都适合 DAG 化" | C3 未验证（U-1）。链存在 ≠ 链可安全复用 |
| "`saved` 大 ⇒ 端到端一定明显加速" | `saved` 是**结构工作量**，不是时间。Poseidon 的 14 没有端到端数据；Orchard 的 1487 ↔ −22% 是单点，不能当斜率外推 |
| "F4-A 是 Halo2 的通用优化" | 样本 2，其中 1 个是合成对照；X5 FAIL |
| "22% 可以移植到其它电路" | 只在 Orchard V3 / `PostNu6_3` 上测过 |
| "n=1 的 −14.35% 代表大规模行为" | n=1 没有跨 action 复用（38 槽），是端点 |
| "两个批次的中位毫秒可以并列" | G2 已证同二进制、同 fixture 也会漂 13% |
| 用 1487 / 621 / 806 互相替代 | 三个层次：每证明结构消除 / 单实例根位置 / product 等价工作量 |
