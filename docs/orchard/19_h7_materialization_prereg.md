# 19 · Stage F3 · H7 预注册：中间向量的物化能不能不付

> **本文件在写任何一行 H7 代码之前定稿并单独提交。** 第 5 节的预测、第 6 节的门槛
> 在看到任何 H7 数字之前固定；结果落在预测之外时，本文件不改，另立"预测失败"记录。
>
> 本轮只做**最小原型**：`Borrowed` / `Owned` 两态返回值 + 二元节点写自己的输出。
> 不引入对象池、不做 CSE、不融合节点、不改分块策略、不改并行结构。

---

## 1. 位置：这是第三类成本

F3 到目前为止测到的是三种互不相同的成本，优化对象完全不同：

| 类别 | 问题 | 实验 | 结果 |
|---|---|---|---|
| 不必要的**计算** | 取负被翻译成整块乘 −1 | **H6** | 40.2% 整块乘法消失，prove **−14.57%**，已冻结 |
| 重复的**计算** | 同一个叶子被求值 31.9 次 | **LC** | 可避免部分只有 12.8%，prove 上界 0.52%，**关闭** |
| 不必要的数据**物化** | 每个节点都要一块新 `Vec<F>` | **H7（本轮）** | 毛上界 **4.04%**，待测 |

H6 与 H7 的分界线要划清楚，否则会把同一笔收益算两次：

- H6 移走的是 `Fp::mul`（每个元素 11.2 ns 的 Montgomery 乘法 → 4 条 `sbb`）。
- H7 要移走的是**搬运**（`to_vec()` 的读 + 写），乘法一笔都不动。
- LC 想移走的是"重读没变的字节"，但 85.5% 的叶子位于必须可写的位置，缓存拿不到。

H7 的关键点在于：**它改变了"谁负责分配"**，因此 LC 的那个 85.5% 结论不再是障碍。
`Mul(q_m, a)` 现在会先 `q_m.to_vec()` 再就地乘，H7 让它直接读 `q_m`，把乘积写进
一个新缓冲区——叶子的那份拷贝根本不需要存在。

## 2. 目标数据结构

```rust
enum EvalValue<'a, F> {
    Borrowed(&'a [F]),
    Owned(Vec<F>),
}
```

执行纪律（本轮固定的四条）：

| 节点 | 规则 |
|---|---|
| `Ast::Poly` | `rotation == 0` 且 chunk 连续 → `Borrowed(&poly.values[start..end])`；否则走原 `get_chunk_of_rotated` → `Owned` |
| `Add` / `Mul` | 两侧都 `Borrowed` → `collect` 出一个新 `Owned`；有一侧已 `Owned` → **就地**累加到它上面（`Add`/`Mul` 在域上可交换，按需交换左右操作数，结果逐位不变） |
| `Scale` / `Neg` | 子节点 `Owned` → 就地；`Borrowed` → `collect` |
| `DistributePowers` | 累加器 `Owned`（`constant_term` 起步），每个 term 只读 |
| 根 | `out.copy_from_slice(root.as_slice())`——与今天完全一样的一次拷贝，**本轮不优化**（见 §8） |

三条必须写明的边界：

1. **"就地复用 `Owned` 左操作数"不是新增优化**，它是现有语义（今天的 `recurse` 就是
   复用它递归拿到的那个 `Vec`）。若不保留，H7 会在纯计算子树上产生回退，那样测出来的
   不是"去掉物化"的效果，而是"加了分配"的效果。
2. **`rotation != 0` 的叶子仍然物化。** H6 树上这类访问占 616/4632 = 13.3%
   （`rotation ∈ {−6: 4, −1: 68, +1: 544}`）。本轮不做"两段拼接的借用"，
   因此**不主张**这 13.3% 的收益。它们留在毛上界之外。
3. **不做对象池。** 分配的**次数**是本轮的核心指标之一（LC 曾估"净增约 1800 次
   分配/chunk"），必须先看清真实数字再谈池化。

## 5. 预测（可失败的）

H6 树的精确结构（D3，`poly_len = 16384`，`chunk = 4096 × 4`）：

```
poly 4632   add 3344   mul 3086   scale 416   neg 2638
distribute 1（430 term）   linear 30   constant 2198   nodes 16345
当前分配次数 = 4632 + 2198 + 30 + 1 = 6861 / 次求值
当前物化字节 = 6861 × 16384 × 32 B = 3.598 GB / 次求值
```

| # | 预测 | 若失败意味着 |
|---|---|---|
| **P1** | 叶子访问仍为 **4632**；`Borrowed` **4016**、`Owned` **616**；叶子拷贝字节 2.4285 GB → **0.3229 GB**（−86.7%） | 借用路径没覆盖到，或旋转分布与 LC 普查不一致 |
| **P2** | 分配次数 6861 → **3400–4500**（点估计 3850）；物化字节 3.598 GB → **1.8–2.4 GB** | 分配次数不降 ⇒ "两侧都借用"的节点比预期多，池化成为前置条件 |
| **P3** | 求值器 1P **−6% 至 −11%**（点 −8.5%）。推算：112.4 ms 的叶子物化中 86.7% 可去 → 97.5 ms，占 1144.7 ms 的 8.5% | < −4% ⇒ 拷贝的边际成本在真实循环里远低于孤立基准 |
| **P4** | 1P 完整 prove **−1.8% 至 −3.8%**（点 −2.8%）。推算：97 ms / 2781.4 ms = 3.5%，按 H6 实测的吸收率 0.95 折 | CI 跨 0 ⇒ 求值器收益不传递 |
| **P5** | 8P 求值器降幅与 1P 接近（差 < 3 pp）。理由与 H6 相反：本次移走的是**搬运**，若 8P 降幅明显更小，说明带宽本来就吃紧 | 8P 明显更小 ⇒ 需要在文档里改写"带宽未饱和"的结论 |
| **P6** | 其余 7 个阶段合计变化在 ±0.5% 内（它们不经过 `recurse`） | 出现成片移动 ⇒ 有跨阶段的副作用，先查再算 |

P1/P2 是**可逐位对账**的：`Borrowed + Owned_leaf = 4632`、`alloc = leaf_owned + constant
+ linear + distribute + both_borrowed`，两个等式在探针里直接 assert。

## 6. 门槛

| 门 | 条件 | 判定 |
|---|---|---|
| **H7-A** 正确性 | ① 逐元素差分：对 `Poly/Add/Mul/Scale/Neg/DistributePowers/Linear/Constant` 每种节点与左右顺序组合，新旧实现在同 chunk 上**逐位**相等；② `Add(a,leaf)` 与 `Add(leaf,a)` 逐位相等（交换律依赖）；③ 真实 Orchard V3 `create_proof` + `verify_proof`；④ 80 次运行全通过 | 必须全过，一条不过即关档 |
| **H7-B** 物化确实减少 | 每次求值 `alloc_bytes` **≤ 70%** 且 `leaf_copy_bytes` **≤ 20%**（相对 A 的解析值）；常量/线性项字节不变 | 证明不是"把拷贝挪到别的节点" |
| **H7-C** 分配次数 | 每次求值分配次数 **≤ 6861**（不增加）；跨 chunk 峰值驻留不增 > 10% | 负面验收 |
| **H7-D** 求值器 | 同进程配对，1P 点估计 **≥ 5%** 且 95% CI 排除 0 | 机制成立 |
| **H7-E** 端到端 | 1P 完整 prove **≥ 1.0%** 且 95% CI 排除 0 | **工程门槛**（写在看到数据之前，不随结果改） |
| **H7-F** 8P | 点估计不退化超过 0.5%，且 CI 上限不高于 +1% | 并行无副作用 |
| **H7-G** 其它阶段 | 除 `quotient` 外 7 个阶段的合计 CI 上限 ≤ +1% | 无连带损失 |
| **H7-H** 决定 | H7-A ∧ B ∧ D ∧ E → 保留原型，进入 H7.5 完整化（池化 / 两段借用 / 根直写）；D 过而 E 不过 → 记"收益不传递"并关档；D 不过 → 关档 | 不做事后调门槛 |

**1.0% 的来历**：它是本轮之前定下的工程门槛，不是从数据反推的。H6 的 14.57% 已经把
求值器里最贵的一类错误拿掉，剩下能拿的是搬运；搬运在 2781 ms 里最多值 4.04%，
扣掉 `rotation != 0` 的 13.3% 后毛上界 3.5%，再扣掉分配与遍历的净增，
2%–3% 是这条路的现实上限。低于 1% 时，继续投入到缓冲区纪律上的性价比不如回到
约束系统层（多个 gate 的合并、selector 复用），那条路在 Stage F 一开始就被押后了。

## 7. 本轮不回答的问题

| 问题 | 为什么不在这一轮 |
|---|---|
| 对象池能省多少 | 池化是"在 H7 之上"的独立因素，混在一起无法归因；先看 §5 P2 的真实分配次数 |
| 两段借用（`rotation != 0`）值不值 | 13.3% 的叶子，收益上界 15 ms（0.5% prove），留给 H7.5 |
| 根直写能省多少 | 一次 chunk 拷贝，~0.08% prove，不值得单独一轮 |
| 峰值 RSS 的精确分布 | 只能采到进程级峰值工作集（外部采样），allocator 内部碎片测不到 |
