Stage F4 -- Constraint-system reconnaissance
===========================================

Built 2026-11-04 on the same host as F0-F3 (i7-14700, P-core logical 0-7 = 0xFF).
This round has no A/B: it is one binary that prints a census. Nothing is timed
against anything, so no pinning was used (the `--mode recon` proof below ran on
the default rayon pool; the one microbench it reports, `eval_polynomial`, is a
single-threaded serial loop).

Tree
----
Vendor = frozen baseline (as restored by `git checkout --`) + f4 patch only.
H6 (`Neg`) and H7 (`Borrowed`/`Owned`) are evaluator-only patches and are NOT
applied here. That is legitimate for this round because the census reads the
`ConstraintSystem`, and the proof bytes prove the CS is the same either way:
`--mode recon` produces proof fingerprint 0xa6bcd171d69e969a and 7264 bytes,
which is the same pair recorded in f3_h6/ and f3_h7/. Same transcript bytes
implies the same constraint system and the same witness.

Commands (from experiments/transaction_e2e/harness)
---------------------------------------------------
  git checkout -- ../vendor/halo2_proofs-0.4.0
  git apply ../vendor/halo2_proofs-0.4.0-f4-recon.patch
  cargo build --release --offline --features f4 --bin orchard-e2e
  ./target/release/orchard-e2e --mode recon --reps 200   > recon_on.log
  ORCHARD_F4=0 ./target/release/orchard-e2e --mode recon --reps 0 > recon_off.log
  # then restore: git checkout -- ../vendor/... && rm -f ../vendor/.../src/f4.rs

  selectors and their activation matrix still exist: `compress_selectors`
  consumes them. Nothing in `ConstraintSystem`, `Gate`, `Selector` or the
  circuit layout is modified -- this is a dump, not a change.
